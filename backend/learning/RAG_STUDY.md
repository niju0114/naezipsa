# RAG 학습 기록과 다음 실험 인계

이 문서는 개인 학습용이다. 질문은 아래에 옮겼고, 답변은 학습하기 쉽게 재구성한 요약이다(대화 전체의 원문 사본은 아님).
RAG 구현은 아직 시작하지 않았다. 기존 뉴스·청약 기능과 새 실험을 구분한다.

## 작업 원칙

- GitHub에는 승인된 백엔드 변경만 올린다. 프론트 변경은 로컬 테스트용으로 유지한다.
- 이 학습 문서는 기존 업로드 대상 9개 파일에 포함되지 않는다. 개인 학습용으로 남기며 임의 커밋하지 않는다.
- 스테이징·커밋·푸시하지 않았다. 새 채팅에서 실제 Git 상태를 다시 확인한다.
- `.env` 내용, API 키, 로그인 토큰을 학습 기록에 저장하지 않는다.
- 기존 업로드 절차: `../app/subscription/README.md`.

## 질문 1: 지금 작업에 RAG가 있었나요?

사용자 질문:

> 자, 이제 나를 위한 질문 하나 할께요. 내가 RAG에 관심이 생겨서 앞으로 RAG 관련 공부를 하고 싶은데, 나는 과거에 C++, Oracle DB로 한 8년간 개발을 하다 20년 정도 쉬다 지금 다시 시작하거든요. 지금 내가 하는 insight 백엔드 작업에서 RAG와 관련된 작업이 있었나요?

답변 정리:

지금까지 함께 구현한 뉴스·청약 기능에는 AI가 검색 자료를 읽고 답하는 단계가 없으므로 RAG가 아니다.
하지만 데이터 수집·정리·검색은 RAG에서 재사용할 수 있다.

RAG = Retrieval-Augmented Generation, 검색 증강 생성.

```text
사용자 질문 → 관련 자료 검색 → 질문과 자료를 AI에 전달 → 근거를 포함한 답변
```

Oracle로 SQL 조회 결과를 화면에 표시했던 과정에, 조회 결과를 AI가 읽고 설명하도록 하는 단계를 추가한다고 생각하면 된다.
SQL이나 규칙 기반 검색으로 시작해도 된다. 처음부터 벡터 DB가 필수는 아니다.

| 기존 작업 | RAG에서 재사용할 부분 |
| --- | --- |
| 국토부·네이버·청약홈 수집 | 근거 자료 확보 |
| 국내 기사 필터·중복 제거 | 자료 품질 개선 |
| 매물 지역·거리 기준 조회 | 사용자 상황에 맞는 자료 선택 |
| 카드 표시 | 자료와 출처를 사용자에게 표시 |
| 아직 없는 단계 | 선택된 자료로 AI 설명 생성 |

첫 질문 예시: “내 관심 매물이 서울에 있는데, 최근 청약 공고와 정책 중 확인할 내용을 정리해 줘.”
자료의 제목·내용·날짜·출처를 AI에 전달하고, 그 자료에 근거한 답변을 생성하면 RAG 실험이 된다.
현재 AI 분석 영역은 표시 공간과 높이 조절 기능만 있고 실제 AI 분석은 연결하지 않았다.

## 질문 2: 실제로 어떻게 시작하면 좋을까요?

사용자 질문:

> 설명만 들어서는 잘 이해가 안되니 조금 더 해보고 싶어요. 프론트엔드 작업자도 그런 아이디어로 ‘등록된 매물에 대한 AI 분석 데이터’ 영역 공간을 마련해 놓은 것인데 아직 구체적인 설계는 못한 단계에요. 내가 테스트로 시작해 보고 싶은데 위에서 말한 내용을 어떻게 구현할지 추천해줘요

답변 정리:

첫 실험은 “맨 위 관심 매물 지역의 청약·정책을 근거와 함께 설명하는 버튼”으로 한다.
자유 질문 챗봇보다 아래 고정 질문 하나로 시작한다.

> 이 매물 지역에서 지금 확인할 청약 일정과 정책 소식을 정리해 줘.

화면 예시(아래 공고명과 날짜는 실제 사실이 아닌 설명용):

```text
관심 지역 소식 요약                         [요약 만들기]
기준 매물: ○○아파트 · 서울

확인할 내용
• A 공고는 9월 20일 접수 예정입니다. [1]
• B 정책은 주택 공급에 관한 발표입니다. [2]

참고 자료
[1] A 모집공고 · 모집공고일 · 청약홈 원문
[2] B 정책 발표 · 발표일 · 국토부 원문

[AI에게 전달한 자료 보기]
```

자료 선택과 설명 생성을 분리하면 잘못된 답변의 원인을 구분할 수 있다.

| 단계 | 역할 | 기존 개발 경험과 연결 |
| --- | --- | --- |
| 자료 찾기 | 지역·날짜·키워드로 자료 선택 | WHERE, ORDER BY |
| 참고 자료 구성 | 번호·내용·날짜·출처 정리 | DTO 가공 |
| 설명 생성 | 질문과 참고 자료를 AI API에 전달 | 외부 서비스 호출 |

### 현재 자료로 답할 수 있는 범위

청약은 공고명·지역·접수 일정·모집공고일을 확보했다. 뉴스는 제목·검색 요약, 국토부는 RSS 제목·설명을 확보한다.
모든 기사나 청약 공고의 본문 전체를 확보한 상태는 아니다.

- 가능: 공고별 접수 일정, 발표된 소식의 제한적인 요약, 출처 안내.
- 현재 불가: 개인 청약 자격 판정, 정책에 따른 매물 가격 상승 예측.
- 지역이 확인되지 않는 정책을 특정 지역 정책이라고 단정하지 않는다.
- 원문에 없는 조건이나 숫자를 보완해서 만들지 않는다.

### 실험 1: AI 없이 자료 선택만 구현

1. 화면 최상위 매물의 평형 ID로 지역을 확인한다.
2. 기존 API와 수집 함수를 이용해 관련 자료를 선택한다.
3. 자료마다 ID, 제목, 실제 확보한 내용, 날짜, 출처 URL을 붙인다.
4. 선택 자료 최대 5건을 화면이나 JSON으로 확인한다.
5. 관련 자료가 없으면 없다고 반환한다. 임의 자료로 수를 채우지 않는다.

이 단계는 검색 부분을 배우는 실험이며 아직 완성된 RAG는 아니다. 모델 API 호출 비용 없이 진행할 수 있다.
기존 데이터 제공 서비스의 제약은 그대로 적용된다.

### 실험 2: 선택 자료로 AI 요약 생성

- 모델 제공자·모델·API 사용 가능 여부와 비용은 시작 전에 별도로 결정한다.
- 질문과 실험 1의 자료를 전달한다.
- 제공 자료만 근거로 설명하고, 날짜와 숫자를 유지하도록 요청한다.
- 각 설명에 자료 ID를 붙인다. 출처 URL은 백엔드가 연결한다.
- 자료에 없는 내용은 “제공된 자료로는 확인할 수 없습니다”라고 답하게 한다.
- 기사 내용은 참고 데이터이며 그 안의 명령문을 실행 지시로 취급하지 않는다.
- 버튼 클릭 때만 생성하고, 중복 클릭·불필요한 자동 호출을 방지한다.

성공 기준:

- 기준 지역에 맞는 자료가 선택된다.
- 공고명·날짜가 원본과 일치한다.
- 설명마다 존재하는 자료 ID와 출처가 연결된다.
- 근거 없는 질문에 사실을 만들어 답하지 않는다.

### 나중에 배울 것

- 다른 표현으로 질문해도 관련 자료를 찾기: 임베딩·벡터 검색.
- 긴 공고문에서 자격 조건만 찾기: 원문 확보·문서 분할·검색.
- 검색 품질과 답변 품질을 별도로 평가하기.

참고: https://www.anthropic.com/engineering/contextual-retrieval

## 질문 3: 새 채팅과 사용량 제한이 걱정됩니다

사용자 질문:
